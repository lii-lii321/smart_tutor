> 文档用途：产品/运营/技术交接的完整说明，覆盖产品定位、业务规则、功能明细、系统架构与运维手册。

## 1. 产品概述

### 1.1 一句话定位

**连接家教中介与大学生教员的撮合平台**：中介把微信群里零散的家教需求批量结构化为订单并挂到公开橱窗，教员按画像匹配投递，中介在线管理「候选 → 定金 → 试课 → 尾款 → 成交」全流程与资金台账。

### 1.2 解决的问题

| 现状痛点 | 平台方案 |
|---|---|
| 订单信息散落在微信群，靠人肉转发 | AI 批量解析微信文本 → 结构化订单（科目/薪资/地址/频次），人工确认后一键上架 |
| 教员找单靠刷群、信息不透明 | 公开橱窗地图（按中介邀请码）+ 个性化推荐（科目/年级/距离/院校匹配分） |
| 定金/尾款线下收钱无台账 | 每笔资金动作强制登记流水（收定金/收尾款/退款/没收），台账自动守恒 |
| 家长联系方式被滥用 | 敏感信息分级脱敏：教员只有在「试课中/已付尾款」状态才能经卡点解锁家长电话与门牌 |
| 中介与教员纠纷无据可查 | 资金操作全量审计（谁、何时、从哪个 IP）+ 状态机防非法流转 |

### 1.3 三类角色

| 角色 | 入口 | 核心诉求 |
|---|---|---|
| **教员（C 端）** | `/teacher/*`（H5，移动优先） | 找单投递、管理简历、跟踪投递进展、查费用与评价 |
| **中介管理员（B 端）** | `/admin/*`（后台，兼容桌面） | 批量进单、审投递、收款项、管教员、看经营数据 |
| **平台老板（超管）** | `/teacher/login` 的老板入口标签 | 管中介账号、看全平台经营统计、封禁违规教员、审计 |

### 1.4 关键约束（业务红线）

- 教员**必须先被中介确认收到定金**，才能开始试课（防绕过中介拿家长联系方式）；
- 订单**只能有一场进行中的试课**；成交时其余候选自动关闭，**已付定金者自动登记退款**；
- 教员付款后中介**改价不追溯**（定金确认时点锁定费率快照）；
- 所有资金动作有流水、有审计、可对账（净额守恒有测试锁定）。

## 2. 核心业务流程

### 2.1 订单生命周期（订单状态机）

```
recruiting（招聘中）
   │  教员投递 → 候选 → 确认定金（订单保持招聘中）
   ▼
trial_in_progress（试课中）──确认尾款──▶ balance_paid（投递层面）──确认完成──▶ completed（成交，终态）
   │  试课失败/违约/教员取消                                      │
   ▼                                                             ▼
recruiting（重新开放，需先处置资金）                          只读，不可再变更
任意活跃状态 ──归档──▶ archived（已归档）──重开（需资金守卫通过）──▶ recruiting
```

### 2.2 投递状态机（教员侧视角）

```
pending（待审核）
  ├─ 中介拒绝 ──────────────▶ rejected（可恢复/可重投）
  ├─ 教员取消 ──────────────▶ rejected
  ├─ 加入候选 ──▶ shortlisted（候选）
  │                  ├─ 确认定金（写费率快照 + 定金流水）──▶ deposit_paid
  │                  │        ├─ 开始试课 ──▶ trial_in_progress ──确认尾款──▶ balance_paid ──完成──▶ completed
  │                  │        ├─ 试课失败 ──▶ refunded（登记退款流水）或 forfeited（零退款补没收）
  │                  │        └─ 教员违约没收 ──▶ forfeited
  │                  └─ 成交时未成交 ──▶ refunded（已付定金，自动退款流水）/ rejected（无资金往来）
  └─ 教员重新投递 ──▶ pending（复用同一行，清空上一轮费率快照）
```

### 2.3 资金流规则（信息费模式）

- **全额信息费** = 单次课酬 × 频次倍率，拆成「定金 100 元（平台锁定）+ 尾款」；
- **频次倍率**：一周 1 次 ×1.5，2 次 ×1.0，3 次 ×0.9，≥4 次 ×0.8，**寒暑假单 ×2.5**；
- **自带价订单**：base_price=0，按教员报价在投递时精算，导入与展示层金额一律服务端置零；
- **试课失败退款** = max(0, 已交信息费 − 家长已付试课酬 × 70%)，封顶实收；教员违约则全额没收；
- **快照口径**：确认定金那一刻把「全额/定金/尾款」三值快照到投递上，之后的尾款、退款、没收全部读快照；
- 金额计算全程 Decimal（ROUND_HALF_UP 到分），避免浮点对账误差；资金写入全部行锁 + 状态守卫 + 同一事务。

### 2.4 信息解锁卡点

家长真实门牌与电话**只**存在于订单的加密字段，教员侧任何列表/详情/橱窗均脱敏（联系方式掩码、坐标降精度到小区级），唯一获取途径：

```
GET /api/v1/orders/{id}/address-unlock
前置：该教员在此订单的投递状态 ∈ {试课中, 尾款已付}
```

## 3. 功能明细

### 3.1 教员端（C 端 H5）

| 简历库 | 个人中心 | 多份简历，默认互斥；首份自动设默认；删除默认后最新剩余自动继承；完善度引导 |
| 推荐 | 橱窗推荐抽屉 | 登录后按科目/年级/距离（常驻地坐标）/院校标签算匹配分，已投递去重，黑名单/封禁屏蔽 |
| 通知 | 个人中心 | 投递全流程站内提醒（候选/定金/试课/成交/退款/没收），未读角标 + 一键已读 |
| 费用 | 个人中心 | 累计支付/已退/没收三卡 + 流水明细 + CSV 导出 |
| 评价 | 个人中心 | 中介对成交订单的星级评价（一单一评），均分展示 |
| 账号 | 登录/注册/个人中心 | 手机号+密码+邀请码登录注册；修改密码（旧 token 立即全端失效）；资料编辑（常驻地定位逆地理编码到「城市·区」粒度） |

## 4. 系统架构

### 4.1 技术栈

| 层 | 选型 |
|---|---|
| 后端 | Python 3.11 · FastAPI（全异步）· Pydantic v2 · SQLAlchemy 2 async |
| 数据库 | 生产 MySQL 8（aiomysql，会话时区锁 UTC）；本地 SQLite |
| 缓存/队列 | Redis 7（GEO 地图索引、分布式限流、调度锁、橱窗缓存；**全部有降级路径**，Redis 挂了照常服务） |
| 前端 | Vue 3.5 + Vite + TypeScript（strict）+ Vant 4（H5）+ Tailwind；Pinia；vue-router 角色守卫 |
| AI/外部服务 | DeepSeek（订单解析）、高德（地理编码 + JSAPI 地图，JS/REST key 分离） |
| 可观测 | 结构化日志按天轮转 14 天；Sentry（前后端，DSN 留空即完全关闭） |
| 部署 | Docker Compose 五服务：db / redis / api（2 workers，非 root）/ scheduler（独立调度容器）/ web（nginx 静态 + 反代） |

### 4.2 服务拓扑

```
浏览器 ──HTTP──▶ web(nginx: 静态资源 + /api 反代 + X-Real-IP)
                      │
                      ├──▶ api(uvicorn ×2 workers) ──▶ MySQL 8（volume 持久化）
                      │        │                      └─ Redis 7（GEO/限流/缓存）
                      └──▶ scheduler(独立容器，心跳 healthcheck)
                               订单过期归档 + 临期提醒（Redis 分布式锁防多实例重复执行）
```

### 4.3 关键数据模型（10 张表）

`tenants`（中介+邀请码+密码）、`teachers`（教员+院校标签+常驻地+封禁+token 吊销标记）、`orders`（订单+精算三值+脱敏字段+过期与周期标记，租户内 raw_id 唯一）、`applications`（投递+状态+费率快照 fee_*，教员×订单唯一）、`financial_records`（四类流水：deposit_in/balance_in/refund_out/forfeit）、`notifications`（教员/租户双通道）、`order_reviews`（一单一评）、`tenant_teacher_blacklist`（租户级黑名单）、`audit_logs`（资金审计）。

### 4.4 可靠性设计

- **资金正确性**：Decimal 精算；写路径 `FOR UPDATE` 行锁 + 状态守卫；净额守恒有测试锁定；成交自动退款兄弟投递（定金黑洞已封堵）；定金时点费率快照；
- **降级链**：Redis 不可用 → 限流退化为进程内、GEO 退化为直查 MySQL、橱窗缓存失效仅 TTL 兜底；DeepSeek/高德失败 → 解析退回人工、坐标退回区县兜底表；
- **令牌治理**：JWT 72h；改密/重置立即全端失效（token_valid_after 时间戳）；中介停用每请求回查即时生效；
- **并发防护**：同订单并发资金操作行锁串行化；调度多实例 Redis 锁去重；投递唯一约束防双击。

## 5. 安全与隐私

| 维度 | 措施 |
|---|---|
| 认证 | bcrypt（线程池防阻塞）；登录/注册全入口限流（IP+账号，Redis 共享计数）；错误文案统一防账号枚举；老板访问码常数时间比较 |
| 授权 | 路由级角色守卫工厂；租户隔离统一走 `assert_tenant_scope`（越权统一 404 防资源枚举）；横向越权有参数化矩阵测试锁定 |
| 隐私 | 家长电话/门牌仅尾款卡点可取；教员/公开视图坐标降精度 + 原文联系方式掩码；AI 解析日志先脱敏再落盘；Sentry 不采集 PII |
| 输入 | 全部走 Pydantic 边界校验（金额上限/坐标范围/文本长度）；SQL 全参数化 + LIKE 转义 |
| 生产红线 | JWT_SECRET ≥32 位、OWNER_ACCESS_CODE 禁默认、AUTO_CREATE_SCHEMA 禁开——config 启动即拒 |
| 审计 | 五类资金动作全量审计（操作人/对象/IP） |

## 6. 部署与运维

### 6.1 首次部署（详见 `DEPLOY.md` + `docs/DEPLOY_CHECKLIST.md`）

```bash
cp .env.production.example .env.production   # 逐项填写（含 MYSQL_ROOT_PASSWORD，必须与业务密码不同）
docker compose --env-file .env.production up -d --build
docker compose exec api alembic upgrade head  # 首次建表
curl http://<IP>/health                       # {"status":"ok"}
```

五个服务全部带 healthcheck（api 打 /health、scheduler 按心跳文件年龄判假死、web wget 探活）。

### 6.2 发版标准序列（DEPLOY.md §4.1）

```
备份 → up -d --build → alembic upgrade head（幂等）→ /health 验证
回滚三层：代码回滚（直接切旧版重建，schema 兼容）/ 迁移回滚（downgrade -1）/ 数据回滚（备份恢复，最后手段）
```

### 6.3 环境变量（`.env.production.example` 为准）

必填：`DB_PASSWORD`、`MYSQL_ROOT_PASSWORD`、`JWT_SECRET`、`OWNER_ACCESS_CODE`、`DEEPSEEK_API_KEY`、`AMAP_API_KEY`；
选填：`WX_APPID/WX_SECRET`（微信登录）、`SENTRY_DSN`、`ALLOWED_ORIGINS`、`LOG_LEVEL/LOG_DIR`、限流三键、`OWNER_TOKEN_VALID_AFTER`（批量吊销老板会话）；
前端：`frontend/.env.production` 的 `VITE_AMAP_KEY`（JSAPI）、`VITE_AMAP_REST_KEY`（Web 服务 REST，推荐分离）、`VITE_SENTRY_DSN`。

### 6.4 日常运维

- **备份**：`docker compose exec db sh -c 'mysqldump ...' > backup_$(date +%F).sql`（建议 cron 每日）；
- **日志**：`docker compose logs -f api`；应用日志容器内按天轮转保留 14 天；
- **临期提醒**：订单到期前 24h 自动通知租户；过期自动归档（有已收款投递的订单跳过，先处置资金）。
