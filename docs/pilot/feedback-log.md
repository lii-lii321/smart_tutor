## 三、七个观察指标（人工观察即可，无需数据分析）

| # | 指标 | 记录方式 | 观察结果 |
|---|---|---|---|
| 1 | **首次录单时间** | 从复制微信订单到订单成功创建大概多久 | |
| 2 | **AI 修改比例** | 如 10 条：几条直接确认、几条要改（比"AI 准确率 95%"这类开发者指标有意义） | |
| 3 | **最常打开的页面** | 订单列表被反复打开而 Workbench 没人看 = 信息架构重要信号 | |
| 4 | **Workbench 是否被理解** | "招聘中 2 / 待审核 0"是否一眼懂（Day 1 重点） | |
| 5 | **是否走完完整链路** | AI录单→订单→教员→投递→审核→试课→成交；不看登录次数看链路断在哪 | |
| 6 | **用户主动绕开了什么** | 设计的路径（Workbench→今日待办→审核）vs 实际路径（Workbench→订单→自己找） | |
| 7 | **愿不愿意继续用** | 直接问："如果明天还继续接单，你愿不愿意继续用？"记原话，不翻译成"满意度较高" | |

## 四、观察清单（按天）

### 第一天——第一印象
- [ ] 登录后第一眼看什么？
- [ ] 能不能马上理解 Workbench（摘要条/今日待办）？
- [ ] "招聘中 2 / 待审核 0"这种数字口径是否容易理解？
- [ ] AI 录单是否真的比手动录单快（让中介现场粘贴一段真实微信文本对比）？

### 第 2~3 天——使用轨迹
- [ ] 中介最常打开哪个页面？
- [ ] 是否频繁返回订单列表？
- [ ] 是否经常进入订单工作区？
- [ ] 哪些字段经常需要人工修改（AI 校对页）？
- [ ] 哪些 AI 解析结果经常出错？

### 第 4~7 天——链路卡点
- [ ] AI录单 → 订单 → 教员 → 投递 → 审核 → 试课 → 成交，哪一个环节最卡？

## 五、收集方式约定

- 每条反馈尽量带：页面截图 / 手机型号 / 操作路径

  反馈集中在哪就修哪（AI 就修 AI、审核就修审核），**不为"完成计划"而改计划**
