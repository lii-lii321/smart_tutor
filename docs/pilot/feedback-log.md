# Pilot 反馈台账（真实中介试用 · 2026-09 起）

> 用途：《Batch 04 反馈》确定的 Pilot 阶段（1-2 个真实中介，为期一周）的反馈记录。
> 原则：**记录用户原话**，不要自己把"我找半天不知道去哪审核"总结成"Applications UX 可以优化"——
> 前者是真实需求，后者已经是开发者解释。
> Pilot 版本：`v0.11.0-pilot`（基于 9d81aae+）。

## 二、观察清单（按天）

### 第一天——第一印象
- [ ] 登录后第一眼看什么？
- [ ] 能不能马上理解 Workbench（摘要条/今日待办）？
- [ ] "招聘中 2 / 待审核 0"这种数字口径是否容易理解？
- [ ] AI 录单是否真的比手动录单快（让中介现场粘贴一段真实微信文本对比）？

### 第 2~3 天——使用轨迹
- [ ] 中介最常打开哪个页面？
- [ ] 是否频繁返回订单列表？
- [ ] 是否经常进入订单工作区？
- [ ] 哪些字段经常需要人工修改（AI 校对页）？
- [ ] 哪些 AI 解析结果经常出错？

### 第 4~7 天——链路卡点
- [ ] AI录单 → 订单 → 教员 → 投递 → 审核 → 试课 → 成交，哪一个环节最卡？

## 三、收集方式约定

- 每条反馈尽量带：页面截图 / 手机型号 / 操作路径
- 微信群里聊到的问题当天誊录进本表（原话格式）
- Pilot 结束后：按出现次数排序，产出《Pilot Feedback Batch》修复清单——
  反馈集中在哪就修哪（AI 就修 AI、审核就修审核），**不为"完成计划"而改计划**

## 四、Pilot 结束后的决策门

- [ ] 反馈修复完成（Pilot Feedback Batch）
- [ ] 决定是否启动 Batch 05（SaaS 化，规格书见 `docs/batches/batch-05-saas-spec.md`）
- [ ] 决定 05A-05E 五个子批的优先级是否按反馈调整
