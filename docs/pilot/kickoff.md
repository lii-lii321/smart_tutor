# Pilot 启动包（拿着这份去中介现场）

> 配套 [feedback-log.md](feedback-log.md) 使用：本文管"怎么开起来"，台账管"记录什么"。
> 原则重申：**不给演示，给真实任务**——旁边指导测出来的是你的指导能力，不是产品可用性。

## 一、启动前置（去之前自己过一遍，10 分钟）

- [ ] 生产/演示环境可从对方手机微信直接打开（HTTPS，无"不安全"警告）
- [ ] 给对方创建**专属中介账号**（邀请码 + 一次性初始密码）——不要把你自己的测试账号 tx886 给他
- [ ] 对方手机上存好橱窗链接：`https://域名/teacher/board/<邀请码>`
- [ ] 现场素材：一段他微信群里**真实的**招单文本（提前让他准备，别用你的演示数据）
- [ ] 打印或手机打开 feedback-log.md 的八个观察指标表（现场就要记）

## 二、开场话术（30 秒，把"免费期"说清楚）

> "我做了个给家教中介用的系统，AI 帮你把微信群里的招单变成可以直接发给教员看的订单。
> 现在找两三家真实中介免费用，你们用真实单子帮我踩坑。
> 以后正式版会收月费，早期用户会有优惠——但今天你什么都不用承诺，就用它接今天本来就要接的单。"

要点：**免费有理由**（换真实反馈）、**收费有预告**（不隐瞒，为第 8 个指标的问题做铺垫）、
**任务无增量**（用的是他今天本来就要处理的单，不是给他加活）。

## 三、培训任务卡（递给中介自己照着做，你只在他卡住超过 2 分钟时出手）

### 任务 1：录今天的第一批单（预计 5 分钟）

1. 打开 `后台地址`，输入邀请码和密码登录
2. 点「订单管理」→ 右上「**录单**」
3. 把他微信群里那段真实招单文本原样粘贴进去 → 点解析
4. **对照微信原文逐单检查** AI 解析结果（地址对不对、价格对不对），改完点确认
5. ⏱ 记下：从粘贴到创建完成用了几分钟（台账指标 1）

### 任务 2：把订单发给教员（预计 3 分钟）

1. 把橱窗链接发给一个他认识的真实教员（微信里现发）
2. 让那个教员浏览橱窗、挑一单投递
3. ⏱ 记下：教员问的第一个问题是什么（这就是你的产品文案要改的地方）

### 任务 3：审核这条投递（预计 5 分钟）

1. 回到后台，「投递审核」里应该出现了刚才那条投递
2. 自己走完：通过 → 确定试课（定金流程按他线下的真实习惯操作或跳过）
3. ⏱ 记下：哪一步他回头问了你"这是干嘛的"

### 任务 4：明天继续（关键）

- **不要教他所有功能**。只说："明天接单就照任务 1 这样录，遇到任何不顺手的直接微信跟我说。"
- 第二天主动问一句："昨天录了几单？哪几单要改？"（台账指标 2 的数据来源）

## 四、第一天你的现场观察（不看屏幕看人）

- [ ] 登录后他的眼睛先看哪里？
- [ ] 「工作台」的数字他念得出来吗（"招聘中 2 / 待审核 0"能不能复述）？
- [ ] 录单时他是逐字核对还是直接确认？
- [ ] 他有没有试图找某个"你觉得很明显"的功能而没找到？
- [ ] 全程他掏出手机几次？（掏手机 = 现有工作流还在微信里）

## 五、一周后的收尾动作

1. 台账按出现次数排序，产出《Pilot Feedback Batch》修复清单
2. 指标 7 + 8 一起看：**愿意继续用 + 报得出价钱** = Batch 05 SaaS 化动工的绿灯；
   只满足前者 = 先解决留存问题再谈收费
3. 把两个中介的原话原样贴进决策记录——三个月后你会需要它们来对抗自己的产品直觉
