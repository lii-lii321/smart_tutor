把"系统登录页"变成"你的入口"

这是给被中介叫来兼职的大学生老师用的页面，不是给企业管理员用的。它应该像微信、小红书登录那样：安静、清楚、一步到位。现在的版本是标准后台模板——76px 深蓝方块 + 组件库通用图标 + 撑出来的空白。

三段文字砍到一段 · 邀请码从输入框变成归属信息

四个问题，第一个是 CSS 副作用

1按钮和输入框之间的空白是撑出来的，不是设计的

/* main.css:176-188 */
.login-form { min-height: 248px; justify-content: flex-start; }
.login-form > button:last-child { margin-top: auto; }

卡片被硬撑到 248px，按钮被推到最底。三个输入框和"登录"之间那道大空隙，是这条规则的结果。截图里能直接看到——密码、邀请码和登录按钮之间隔着一片白。

删掉 min-height 和 margin-top: auto，卡片高度跟随内容，按钮紧跟第三个字段。

276px 深蓝方块里放的是组件库图标

van-icon name="manager-o" 是个通用人形——这是 Vant 的现成素材，不是这个产品的标识。加上 22px 圆角和 0.18 投影，标准的demo 登录页长相。

换成「智」字，浅底深字，48px。这是品牌自己的字，比借来的图标有识别度。

3已回填的邀请码，长得跟要手输的一模一样

Login.vue:54 已经从 ?inviteCode= 回填了（你截图里那个 tx886）。但它仍是三个等权的输入框，用户不知道不用管它，也不知道自己是从哪家中介进来的。

回填时改成只读的归属卡：中介名 + 邀请码 + ✓。没有回填才显示输入框。

4五段文字互相稀释

品牌名、tagline、note、中介合作、协议——从上到下五段。真正要做的只有一件事：填手机号、密码、点登录。而 note 里的"密码遗忘请联系中介重置"和下面的"前往中介后台"其实在说同一件事。

收到两段，note 拆散到该出现的那一刻——密码报错的行内提示里才提"忘记密码请找 XX 中介"。

5眼睛图标是"半闭眼"

closed-eye 是个半闭眼的表情包，密码框里放这个很出戏。而且它没有明确的可点样式，不像个能点的开关。

换成标准 eye / eye-off 线性图标，加 44×44 的可点区域。

成品对比

切「现状 / 未带邀请码 / 已回填」三个状态。中间那个是直接访问登录页的样子，最常见；右边是从中介分享链接进来的样子。

重设计版：品牌区从 178px 压到 94px，表单贴着内容走。整页文字只剩三处——品牌名、密码 placeholder、底部两行。

关键一招：邀请码不是"第三个输入框"

三种入场方式，三种表达。这是这页最值得改的一处。

✓从中介链接进来（有邀请码）

URL 带 ?inviteCode=tx886，用户从中介转发的小程序/链接点进来。他根本不需要知道"邀请码"是什么概念——那是中介之间的事。

显示成只读归属卡：中介名 + 邀请码 + ✓。暖纸底，无输入框边框。顺带解决了信任问题——"我是从哪家中介进来的"一眼可见。

✓直接搜 URL 进来（无邀请码）

不知道邀请码从哪来，或者中介只发了口头。这才是真需要指导的场景，原来完全没有。

显示输入框 + 一行说明：「没收到？联系推荐你来的中介要，格式通常是 3~6 位字母数字」。格式和来源都给了，不用猜。

改动清单

三个角色（教员 / 中介 / 老板）共用 Login.vue，这套骨架字段数不同但结构一致，不用拆成三个页面。

要提的一处产品缺口

归属卡上写的「明德教育」只是演示名字。真要让这张卡成立，后端得能通过 inviteCode 反查中介名——现在 /tenants/my-teachers 之类的接口没提供这个反查。如果暂时不想加接口，卡片就只显示邀请码和"来自中介推荐"，不显示具体名字。这点需要你定。
