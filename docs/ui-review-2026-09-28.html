UI 深度评审 · 2026-09-28

你的设计系统是对的,但它没有在运行时生效。

智派家教有一份质量相当高的 design token：Navy 品牌色阶、暖纸背景、语义化状态色、统一的圆角与阴影尺度，全站单一来源。 真正的问题出在 token 之外——它被 454 处裸写的 slate 色、5 套各自为政的宽屏策略、以及一条全局 !important 劫持的圆角规则架空了。 B 端在桌面上的核心矛盾不是"不好看"，而是它从来没有过桌面形态——一张 672px 的手机卡片流，被居中放在 1920px 的屏幕中央。

454SLATE 裸色 / 处

一屏读懂：体系层面无需推翻，需要的是三件事——① 收口颜色，恢复 token 的唯一性；② 给 B 端一个真正的桌面外壳（宽侧栏 + 表格 + 批量），而不是逐页猜 max-w；③ 把"信息费 / 定金 / 垫付风险"提升为 C 端的视觉主角，这是整个产品唯一的决策核心，却被埋在一行小字里。

01

现状诊断

全部结论来自源码实读，按影响面排序。右侧为对应修法。

1

桌面端不是设计出来的，是逐页猜出来的

五个后台页有四种宽屏策略。侧栏只有 76px 图标条，没有文字标签、没有分组、没有全局搜索。结果是 1920px 屏幕上，工作台内容挤在 672px 居中，两侧是空白；而订单列表却有完整表格。用户在不同页面之间建立不起"我在同一个系统里"的位置感。

Dashboard.vue:182 · max-w-2xl Settings.vue:139 · max-w-2xl BatchImport.vue:251 · max-w-2xl OrdersList.vue:273 · lg:max-w-6xl ApplicationsReview.vue:393 · lg:max-w-none
修法

抽一个 AdminShell：212px 带文字标签的宽侧栏（经营/订单/投递/资金/系统分组）+ 56px 顶栏（全局搜索 + 通知）。页面只提供内容，不再自己管宽度。

2

Token 纪律已经失效，主题改造会大面积漏网

design-tokens.css 开宗明义写"禁止新增裸写 hex，只允许消费语义类"，但全项目有 454 处 slate-* 裸色，分布在 38 个文件。结果是 bg-slate-50(#f9fafb) 和 bg-surface-soft(#f5f6f7) 在同一个产品里并存两种"浅灰"，肉眼可辨的色差；而"换主题 = 只改一个文件"的承诺已经不成立。

OrdersList.vue · 52 处 BatchImport.vue · 52 处 Tenants.vue · 48 处 Board.vue · 36 处
修法

先补齐 slate 全阶到 token 的映射（--st-slate-*），再开 ESLint no-restricted-syntax 禁掉视图层裸色类。按文件批量替换，一次性收口。

3

C 端在同一趟旅程里换背景色

找单页和订单详情用暖纸 #faf9f7，个人中心、我的投递、注册页却用 bg-slate-50 / bg-gray-50。教员从"找单 → 我的投递 → 个人中心"点三个 tab，底色从暖白跳到冷灰，这是最廉价的一类观感问题，且零风险可修。

Board.vue · bg-page 暖纸 Profile.vue:70 · bg-slate-50 MyApplications.vue:104 · bg-gray-50 Register.vue:96 · bg-gray-50
修法

全局统一 bg-page。三处替换，零改动成本，收益立竿见影。建议列为第一个提交。

4

全局 !important 劫持了 Tailwind 的圆角语义

main.css:51-59 用 !important 把 rounded-2xl 改写成 14px、rounded-xl 改写成 10px。在这个项目里 Tailwind 的圆角刻度已失效，新人或后续的 AI 按 Tailwind 直觉写 rounded-xl 会得到意外结果。而且全站圆角只剩两档，容器层级无法用圆角表达。

main.css:51 · .rounded-2xl → --st-radius-lg main.css:54 · .rounded-xl → --st-radius-md
修法

在 tailwind.config.js 里覆写 borderRadius 指向 --st-radius-*，删掉 !important；同时补 rounded-full 之外的一档 2xl，恢复层级表达力。

5

C 端把内部管道（中介/邀请码）放在了第一视觉位

找单页工具栏里，"当前中介"选择器是最左、最宽的控件，比"筛选"还宽。对一个大学生教员来说，心智是"我要接单"，中介只是订单来源；邀请码属于 URL 层的产品机制。当前设计让一个系统概念占据了用户的第一次注视。

Board.vue:357-368 · 中介选择器 flex-1 Board.vue:365 · 与 筛选/模式切换/登录 挤在同一行
修法

中介降级为一行低调的来源说明（"来自 星光教育·杭州 · 切换"），首屏让位给匹配结果与收入。详见下方 Mockup A。

6

信息费是决策核心，却没有视觉统治力

教员真正在意的三件事是：这一单我能赚多少、要先垫多少、风险多大（试课失败退不退、违约会不会没收）。但当前订单卡里，信息费只是正文中的一个 span，后面紧跟括号里的小字注释；顶部右侧的位置在推荐态被"匹配 92%"占据。而这些风险规则是业务红线，界面上却没有统一的表达组件。

TeacherOrderCard.vue:88-92 · 费用为行内 span TeacherOrderCard.vue:42 · 顶部右侧被匹配分占用
修法

把卡片底部改成"资金条"：信息费大字为主角，定金/尾款降为副信息，右侧补风险徽标（可退/部分退/没收），全站统一。详见 Mockup A。

03

落地顺序

按"改动量 ÷ 观感收益"排序。第一批是几乎零风险的清理，可以立刻做。

  1. Batch 1 · 零风险清理 · 约半天

    把 token 重新变成唯一真相

    统一三处页面底色为 bg-page；把 main.css 的圆角 !important 迁到 tailwind.config.js；补齐 slate 全阶映射并批量替换 OrdersList / BatchImport / Tenants 的 152 处裸色。改完 npm run build 即可验证，零业务风险，但立刻消除所有跨页色差。

  2. Batch 2 · 抽外壳 · 约 2-3 天

    AdminShell：给 B 端一个桌面形态

    新建 AdminShell.vue（212px 分组侧栏 + 56px 顶栏 + 全局搜索），五处 max-w 各自为政的页面统一接入。订单列表的表格逻辑上移到 Shell 的表格容器，B 端从"手机页面放大"变成"桌面工作台"。这是投入产出比最高的一步。

  3. Batch 3 · 提优先级 · 约 2 天

    让信息费成为 C 端视觉主角

    抽出 MoneyBar（信息费大字 + 定金/尾款拆分）与 RiskBadge（可退 / 部分退 / 没收）两个组件，替换 TeacherOrderCard 的行内 span；同时把中介选择器从工具栏首位降到一行来源说明。这两个改动直接作用于转化率，不只是观感。

  4. Batch 4 · 提效率 · 约 3-4 天

    投递审核改三栏 + 批量操作

    左侧投递列表（按状态分组带计数）/ 中间教员档案与匹配分拆解 / 右侧资金与动作；试课失败从弹窗改为内联精算面板（三选项 + 净额预览）。配套给订单列表补多选批量与快捷键——中介每天处理几十单，桌面端必须比移动端快。
