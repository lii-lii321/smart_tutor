顺手发现一个真问题

不算视觉问题，但比视觉严重：四步流程里最长的一步没有兜底。

AI 识别的结果刷新即丢，30 秒白等

rawText 和 parsedItems 都是 BatchImport.vue 的局部 ref，store 里的 batchParse() 只是 return res，不缓存。粘 20 单等 30 秒，中途误触返回或系统回收页面，前功尽弃。

// stores/order.ts:36
async function batchParse(rawText: string) {
  parseLoading.value = true;
  try {
    const res = await ordersApi.batchParse(rawText);
    return res;   // ← 没有任何缓存
  } finally { parseLoading.value = false }
}

四个手法，逐个说

1输入区升格成主角

白底 + brand-300 1.5px 描边 + 投影 + 16px 圆角，占最大面积。全页只有它用这一档。视觉重量一拉开，平铺感立刻消失。

2加"识别后你会拿到"

一行五个字段图标。空状态下用户最缺的就是这个——现在粘完只能干等，完全不知道会得到什么。这不是装饰，是产品承诺的可视化。

3CTA 改用 AI 紫

步骤条第 2 步本来就是紫的，CTA 却藏成藏青，AI 属性被浪费。token 明确规定 --st-ai 用于「AI 解析」，这里正好合规，全页也统一了 AI 语义。

4粘完立刻分段反馈

按空行/【】本地切分，粘完马上显示"识别到 2 段"和每段编号。不用等 30 秒才知道粘对了没有——这是最治"空"的一招，页面瞬间有内容。

改动清单

前 5 条是视觉和交互，最后 1 条是逻辑——也是唯一需要碰 store 的。

现状改成
步骤条、卡片头、输入框全是同一种表达，没有主角 分主角（输入区）/ 配角（AI 提取什么）/ 背景（虚线可选动作）三层，描边粗细、圆角、字号、底色全部拉开
"填入示例"是卡片右上角灰色小按钮 搬进输入区空状态，升级为品牌色主按钮，是空状态下唯一的主 CTA
空状态下用户不知道会得到什么 新增「识别后你会拿到」五行字段图标，把产品承诺前置
步骤条第 2 步是紫的，CTA 是藏青，AI 语义不统一 CTA 改 --st-ai 紫，全页 AI 相关元素统一，符合 token 规定用途
"0 字 · 原文将完整存档"是页面唯一信息 粘完变成分段反馈：段数 + 每段编号，绿底对勾；把最没营养的字数提示换掉
卡片下方 350px 空白，CTA 埋在卡片里 底部固定操作条（沿用现有 bottom-[50px] 逻辑），CTA 进拇指区
rawText / parsedItems 是局部 ref，batchParse() 不缓存 草稿落 sessionStorage，进页自动恢复并提示「上次识别到 N 单，未完成校对」需改逻辑

配色全部取自 frontend/src/styles/design-tokens.css，未新增色相；AI 紫严格按 token 规定仅用于 AI 解析场景。本页为设计稿，不含代码改动。
