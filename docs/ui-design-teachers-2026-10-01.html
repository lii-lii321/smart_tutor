从"名录"变成"人力池"

这页现在每行只回答了三件事：叫什么、投了几次、成交几次。中介老板真正要问的是——这批人里谁最近还在动、谁干净、谁该小心。而这些数据接口全都返回了，前端一个都没显示。

三个结构问题

后两个是代码里能指出来的，不是审美问题。

1"拉黑"红按钮是这页最刺眼的东西

破坏性操作 + 红色 + 每行重复。5 行教员 = 5 个红按钮，页面看着像"处处是警报"。更糟的是它在视觉上比姓名还重，暗示这页主要用途是拉黑——恰恰相反，这页是看人的。

移到行内「···」菜单。破坏性操作不该占据最高对比度的位置。

2"活跃"是个假选项

if (listFilter === "active" && t.is_blacklisted) return false
if (listFilter === "blacklisted" && !t.is_blacklisted) return false

"活跃" ≡ "未拉黑"。三个 chip 实际只有 2 档，而且和"全部 / 已拉黑"是同一维度。用户以为"活跃"是"最近有动作"，点完发现是另一回事。

✓换成可点的真实数字

顶部三个数字本身就是筛选器：12 教员 / 11 可推单 / 1 已拉黑。不再用"活跃"这种含糊的形容词，改成用户能核对的量。

下面再补一句 「5 人在近 30 天投递过」——这才是"活跃"的真正定义，而且数据现成（last_applied_at）。

3违约 0 用了灰色

灰色在界面语言里是"缺失"，但违约 0 是好消息——这个人干净。现在五个人的违约全是 0，五个灰色，看起来像数据没加载出来。

4评分缺失不可见

只有一个人有 avg_rating，其余四人界面直接不显示这一项。用户分不清"评分低"和"还没被评价过"。缺数据要显式画出来：—。

成品对比

同一批人、同一份数据。右边把接口里已有但没用的三个字段接上了：last_applied_at、avg_rating、以及 completed / applications 算出的成交率。

重设计版：行内一个红色都没有，破坏性操作全部收进「···」。信息密度上去了，但视觉更安静。

五种状态，视觉先说话

一屏之内，中介不读文字也能分出谁干净、谁要小心、谁已经出局。

状态视觉信号为什么这么设计
近期活跃 + 干净 绿色「可推单」标 + 绿色时间「今天投递」 这是最想让人快速扫到的一类，双重绿点，视线优先落在它身上
久未活动 时间和文字一起降灰，「21 天前」不做任何强调 不报警，但扫过去能感觉到"这个凉了"。灰色在这里是降温不是缺失
有违约记录 整行琥珀底 + 琥珀「2 次违约」标 违约是"要小心"不是"已拉黑"，用琥珀不用红——红留给不可逆的拉黑
高成交率 成交率数字转绿（≥60%） 成交率比"成交 N 次"更可比。李老师成交 1 次看着不错，成交率 0% 才是真相
已拉黑 整行降透明 + 灰底 + 「⊘」头像 出局的人不该还在列表里争夺注意力，但要留着可追溯

改动清单

全部在前端，接口零改动——用到的三个字段 last_applied_at / avg_rating / 成交率都已经返回了。

现状改成
每行右侧一个红色「拉黑」按钮 移到行内 「···」菜单。列表页红色数量从 N 降到 0，拉黑/移出走同一个菜单项 治结构
全部 / 活跃 / 已拉黑 三个 chip（"活跃"=未拉黑，只有 2 档） 顶部改成 可点击的数字概览：12 全部 / 11 可推单 / 1 已拉黑。筛选器 = 概览，不再重复表达 修歧义
last_applied_at 返回了但没显示 每行右上角显示 最近投递时间；概览底部给「5 人在近 30 天投递过」——这是"活跃"的真实定义 接已有字段
投递 N 次 / 成交 N / 违约 N 三个原始计数 换成 成交率 = 成交 / 投递。同样的数据，换成可横向比较的口径
违约 0 灰色；无评分直接不显示 违约 0 用常规字重（干净是常态）；无评分显式写 「— 未评价」，区分"没数据"和"评分低"
筛选排 + 排序排两排 chip，长得几乎一样 筛选取代进概览，排序单独一行并加 「排序」标签，用竖线分隔不同视图方式
"与你发生过投递关系的教员都在这里"占一整行 标题下不再放说明句（这是默认认知，不是本版要强调的），把空间还给数据

两件要提醒的

一、排序只在已加载分页内生效。usePagedList 是 50 一页，"成交多 / 评分高"目前只对已加载的 50 人排序。教员量几十人时无感，量大了要么调大 page_size，要么把排序下沉到 SQL。
二、配色还悬着。这份稿用的是现有深蓝 token。上一轮的品牌色方向你没定，选定之后这份和前面几份要统一刷一遍色值（版面不用改）。
